# 运行期

> 实例起来之后，插件能观察到的世界由三样东西构成：patch 里的路由、进程环境、home 里的契约。

## harness 读到什么

路由本体在**配置层**，也就是 profile 的那份 patch：协议、地址、密钥变量名、模型表、容量与推理档，都是 HDSL 在启动时写进去的。

**密钥本身在进程环境里**。harness 真正发请求时才去解析 `apiKeyEnv` 指向的那个变量，所以 patch 里没有、也不会有密钥。

玩家对这条路由的偏好（默认模型、推理档）记在 harness 自己的设置层里，由界面维护。

> **提示**：模型页读的就是 profile 的这份 patch，所以启动器写进去的那条路由在运行期是可见、可编辑的。玩家在界面上改它（换模型、改地址）不会报错：路由本来就在编辑器编辑的那份文档里。

## 玩家在运行期改供应商

玩家新加一个自己的供应商时，它写进的是同一个 `llm-pi-ai` 条目的 `config.providers`，与启动器写的那条并存，互不影响。

修改启动器写的那条路由也写得进去，只是下一次用同一账号启动时会被账号的真实信息覆盖：地址和模型表以供应商的回答为准，不以文件为准。把它删掉也有效：本次运行里那条路由就没了，下次用该账号启动会重新写出来。

一句话概括：「账号的路由由账号说了算」。玩家想长期保留自己的模型表，就用自己的路由名，不要叫得和账号一样。

## HDSL 在运行期做什么

**什么都不写。** 启动完成后，启动器只在旁边看着。

* 监视进程状态、就绪信号与端口漂移（端口被别的 patch 层改掉时会报出来）。
* 崩溃时弹一次崩溃对话框，每条结束路径只弹一次。
* 「打开终端」会生成一个脚本，里面 `export` 与本次启动同名的密钥变量，方便玩家在同一个实例环境里手工排查。那个脚本含密钥，而且不会自动删除。

## 插件在运行期能做什么

* **显示当前账号、供应商、头像**：读账号契约，见 [HDSL 插件接入指南](../plugin-guide/README.md)。契约在进程环境与 `home/.env` 里，客户端半边要靠服务端转出来。
* **判断是不是离线账号**：看 `HDSL_ACCOUNT_KIND` 是否为 `offline`。离线账号没有路由，也没有 `HDSL_ACCOUNT_ENDPOINT` 与 `HDSL_ACCOUNT_MODEL`。
* **按供应商做不同行为**：用 `HDSL_ACCOUNT_VENDOR`，不要去解析账号名。
* **找到本账号在 harness 里的路由**：拿 `HDSL_ACCOUNT_ROUTE` 去 patch 的 `config.providers` 里查，查不到就当作没有。
* **让玩家从自己的界面切模型**：用 harness 自己的配置编辑能力，不要自己重写 patch 文件，见[禁止事项](05-plugin-reference.md#禁止事项)。
* **自己调用供应商**：优先复用 harness 已经配好的那条路由。密钥变量名可以由路由名推出，但不要落盘、不要转发。

> **注意**：客户端插件（浏览器里的那半边）读不到进程环境。要显示账号信息，就在服务端半边读契约，再通过自己的路由或接口交给浏览器，做法见[在插件中读取](../plugin-guide/03-read-in-plugin.md)。
