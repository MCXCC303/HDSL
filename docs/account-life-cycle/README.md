# HDSL 账号生命周期

> 一次实例启动里，账号被选中、翻译成供应商路由，运行结束后被回收的完整过程。

本套文档面向 **DSH 插件开发者**，回答三个问题：

* 你的插件在什么时机能看到什么？
* 哪些值可以长期依赖，哪些只在那一次启动里存在？
* 哪些事会打断启动器与 harness 之间的约定？

「账号」是 HDSL 的概念，harness 并不认识它。HDSL 做的是翻译：把「账号 + 供应商」翻译成 harness 认识的一条**供应商路由**（写进 profile 的 patch）和一个**环境变量名**（harness 运行时从这里读密钥）。插件只依赖翻译的结果，不要读 HDSL 自己的数据文件。

如果你只想在自己的界面里显示玩家名和供应商，读 [HDSL 插件接入指南](../plugin-guide/README.md) 就够了。本套文档讲的是那些变量背后的生命周期。

## 一次启动的全貌

```text
点击启动
   │
   ├─ 1 选账号        实例指定 → 全局选中 → 列表第一个
   ├─ 2 验密钥        问供应商 /models；被拒 → 中止启动
   ├─ 3 取模型        问供应商的模型列表；取不到 → 中止启动（账号里写了模型除外）
   ├─ 4 注入          路由 → profile patch   密钥 → 子进程环境
   │                  契约 → 进程环境 + home/.env   便签 → 记录这次动了什么
   ├─ 5 运行          harness 读 patch 里的路由；密钥从环境解析
   │
   └─ 6 子进程退出 ─→ 监听器 ─→ 按便签回收：路由从 patch 取出、settings.yaml 还原
```

每一步的失败行为见[启动](02-launch.md)；各观测点存在多久见下表。

## 观测点

| 观测点 | 里面是什么 | 存在多久 |
|---|---|---|
| 子进程环境 | 密钥、账号契约 | 这一次运行 |
| profile 的 `cordis.patch.yml` | 供应商路由本体（协议、地址、模型表、密钥变量名） | 这次运行，退出即回收 |
| `<实例 home>/.env` | 账号契约（**不含密钥**） | 持久，每次启动重写自己那段 |
| `<实例 home>/settings.yaml` | 默认模型、路由的 `apiKeyEnv` | 历史通道，见[启动](02-launch.md) |

> **注意**：最容易踩的三条线是：路由会消失，不要缓存它的地址；密钥只在进程环境里，不要落盘、不要转发；账号改名等于换了一条路由，老的变量名不再有人设置。
