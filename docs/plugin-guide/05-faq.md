# 5. 常见问题与限制

## 读不到值怎么办

按这个顺序判断：

1. `HDSL_ACCOUNT_CONTRACT` 没有 → **不是 HDSL 启动的**（玩家手工 `dsh web`，或别的启动器）。
   全部回退到你的默认显示，不要报错。
2. 有契约但没有 `HDSL_ACCOUNT_NAME` → 这次启动**没有选账号**。显示「未选择账号」。
3. 有名字但没有 `HDSL_ACCOUNT_VENDOR` → 大概率是**离线账号**（`HDSL_ACCOUNT_KIND=offline`）。

## 玩家手工启动时还有吗

**有，只要你读的是 `user-env` 层。** HDSL 会把同一份契约写进 `<实例 home>/.env`，
harness 每次引导都会读它——包括玩家自己敲 `dsh web`、或用 HDSL「在终端中打开」进去敲的那次。

但只有该实例**被 HDSL 启动过至少一次**才会有这个文件。从没被启动过的 home 里没有。

## 为什么绝对不能写 `DSH_` 前缀

harness 的引导会拒绝任何 `.env` 里的 `DSH_`、`XDG_`、`DYLD_`、`BASH_FUNC_` 前缀，
以及 `PATH`、`HOME`、`LD_*`、`NODE_OPTIONS` 等名字，**并且是抛错拒绝**——
一个这样的变量会让 harness 起不来。所以：

- HDSL 的契约一律 `HDSL_` 前缀；
- **你的插件不要往任何 `.env` 写东西**，尤其别写 `DSH_*`。

## 能拿到 API key 吗

**不能，也不应该去找。** 密钥只在子进程环境里（`HDSL_LAUNCH_API_KEY`），
不写进任何文件；本契约刻意只承载「显示与路由」级别的元数据。
如果你的插件需要调用模型，应当通过 harness 自己的 LLM 服务，而不是自己拿密钥发请求。

## 皮肤文件为什么是绝对路径

因为那就是启动器存放玩家头像的真实位置（`<启动器数据目录>/skins/<hash>.png`）。
绝对路径**只对服务端半边有意义**；浏览器半边拿不到，需要你自己的服务端转发，见
[4.2](04-display-user-info.md)。

> **注意**
> 永远不要把「请求里的路径」当作文件路径去读——那是任意文件读取漏洞。
> 只读你自己从环境里取到的那一个。

## 契约会变吗

- **加变量**：不会递增版本，你本来就该忽略不认识的键。
- **改语义**：递增 `HDSL_ACCOUNT_CONTRACT`。遇到不认识的版本请整体忽略。
- `NAME` 与 `ROUTE` 今天相等；如果你想在未来它们分开时仍然正确，
  **显示用途读 `NAME`，查配置读 `ROUTE`**。

## 我需要声明依赖吗

`@deepseek-ai/dsh-launch-environment` 由 harness 自身提供、与你的插件同进程，
不需要在 `package.json` 里声明版本。它是**库**，不是插件，不要试图从 `cordis.yml` 挂载它。

## 应该什么时候读、读几次

**启动时一次。** 契约在进程生命周期内不变，`process.loadEnvFile` 只在引导时执行一次。
不要轮询，不要放进渲染循环，也不要缓存到磁盘。

## 和「模型供应商」注入是什么关系

HDSL 本来就通过 `--patch` overlay 给实例注入一条 `llm-pi-ai` 路由（模型供应商）。
那份配置回答的是「怎么发请求」；**本契约回答的是「这是谁」**。
两者独立：插件只想知道玩家叫什么，读契约就够了，不需要解析供应商配置。

## 限制一览

| 限制 | 说明 |
|---|---|
| 客户端半边读不到进程环境 | 必须由服务端半边转发 |
| 皮肤只有绝对路径 | 浏览器侧要自己转发图片 |
| 契约可能整体不存在 | 必须回退，且要测这条路径 |
| 不含凭据 | 密钥永远拿不到 |
| 不要在 `.env` 写 `DSH_*` | 会让 harness 起不来 |
